# NOESIS

NOESIS 是一款本地优先的思想写作工具。把想法写成卡片，再把卡片排成章节，最后组合成一套可以连续阅读和导出的思想体系。

**卡片 → 章节 → 体系**

## 核心功能

- 思想卡片只包含标题和正文，支持搜索、编辑、软删除、扑克牌翻面和左右滑动
- 卡片之间可建立无向关联，并从关联卡片直接跳转
- 章节可以引用多张已有卡片；同一张卡片可出现在多个章节中
- 长按拖动调整章节内卡片顺序，也可拖动调整体系内章节顺序
- 按章节或整套体系连续阅读卡片正文
- 一键导出完整思想体系 Markdown 文档
- 本机 SQLite 持久化；“备份”入口支持完整 JSON 备份、恢复和卡片批量导入

## 批量导入卡片 JSON

在 App 右上角打开“备份”，选择“从 JSON 批量导入卡片”。文件可以是卡片数组，也可以用 `cards` 字段包一层：

```json
[
  { "title": "欲望是一种关系", "content": "主体在欲望指向对象的过程中逐渐形成边界。" },
  { "id": "existing-card-id", "title": "自我由叙述构成", "content": "自我通过讲述过去来保持连续。" }
]
```

每张卡片必须有非空 `title`，`content` 可以省略，`id` 可选。没有 `id` 会新增卡片；带有本机已有 `id` 会更新该卡片，省略 `content` 时保留原正文，不改变它的章节和关联。导入前会显示新增、更新数量；整批数据会在一个数据库事务中提交，格式错误时不会导入部分卡片。完整备份恢复是另一项操作，会替换本机全部数据。

## 本地运行

```powershell
npm install
npm start
```

在 Expo Go 中扫描终端显示的二维码。手机和开发电脑需要连接到同一局域网。

## 数据兼容与迁移

现有 SQLite 数据库从 v4 以事务迁移到 v5。卡片仍使用旧 `thoughts` 表保存，以保留卡片 ID 和旧字段；应用层只向新界面提供 `id`、`title`、`content`、时间和软删除状态。旧关联会复制到无向 `card_links` 表供新界面使用，原 `relations`、牌组、标签、来源和修订记录均保留。

迁移新增 `systems`、`chapters`、`chapter_cards`、`card_links` 表，不删除旧表。完整 JSON 备份包含新旧所有表；v1 到 v4 的旧备份仍可恢复，旧卡片关联会在恢复时映射到无向关联。
